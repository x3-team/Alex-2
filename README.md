## Запуск

```bash
npm install
npm run dev      # дев-сервер
npm run build    # прод-сборка в dist/
npm run preview  # посмотреть прод-сборку
```

## Перенос в существующий проект

Если страница 404 встраивается в уже готовое Vue-приложение, из этого
репозитория нужны только пять файлов:

```
src/views/Error404.vue                страница
src/composables/useParticleField.js   привязка к жизненному циклу
src/lib/particle-field.js             движок частиц
src/assets/icons/arrow-right-light.svg
src/assets/icons/arrow-right-dark.svg
```

Плюс переменные из `src/assets/css/tokens.css` — либо файл целиком, либо только
блок с токенами страницы 404 (`--space-*`, `--glass-*`, `--radius-*`,
`--shadow-*`, `--ease-out-soft`, `--duration-*`, `--font-*`, `--color-*`).

Дополнительных зависимостей нет — только Vue 3. Импорты используют алиас `@` на
`src`; если в проекте он называется иначе, поправить нужно три строки в шапке
`Error404.vue` и одну в `useParticleField.js`.

Шрифт страницы — Roboto, подключается в `index.html`.

## Страница 404

### Подключение в приложении

`Error404.vue` не тянет за собой роутер: кнопки по умолчанию рендерятся как `<a>`.
Чтобы переходы шли через vue-router, достаточно передать `RouterLink`:

```vue
<script setup>
import { RouterLink } from 'vue-router';
import Error404 from '@/views/Error404.vue';
</script>

<template>
  <Error404 :link-component="RouterLink" />
</template>
```

Все тексты и список кнопок настраиваются пропсами — `title`, `subtitle`,
`navItems` (элемент вида `{ label, to, primary }`), `fieldOptions`.

Компонент позиционирован `fixed` по вьюпорту, поэтому он самодостаточен и не
требует глобальных стилей на `body`. Из глобального ему нужен только
`tokens.css` — он подключается в `main.js`.

### Фон

В макете фон — растровая картинка с боке-частицами и заливкой
`rgba(0, 0, 0, 0.4)` сверху. В коде она разбита на два независимых слоя:

1. **Градиентная туманность** (`.space` в стилях компонента) — тёплое золото
   сверху слева, холодный синий снизу справа. Остаётся резкой на любом
   разрешении и не зависит от внешнего файла.
2. **Живое поле частиц** (`ParticleField` на canvas) — рисуется поверх
   градиента.

### Движок частиц

`src/lib/particle-field.js` — обычный ES-модуль без зависимостей и без привязки
к Vue. Жизненным циклом управляет композабл `useParticleField`: движок
создаётся в `onMounted` (поэтому он не трогает `document` при SSR) и
уничтожается в `onBeforeUnmount`. Экземпляр хранится в `shallowRef`, а не в
`ref`: это класс с приватными полями, и глубокий реактивный прокси сломал бы
доступ к ним.

**Объём.** У каждой частицы есть глубина `z`. Она определяет размер
(квадратично, поэтому перспектива читается сильнее), расфокус относительно
фокальной плоскости и прозрачность. Ближние частицы — крупные размытые боке,
дальние — мелкие и резкие. Спрайты предрендерятся один раз в офскрин-canvas по
шести уровням размытия, поэтому в кадре нет ни одного дорогого `shadowBlur`.

**Движение разделено на три независимых слоя**, чтобы они не конфликтовали:

- *Ambient drift* — медленное поле потока из больших синусоид плюс личный дрейф
  каждой частицы. Работает всегда и никогда не затухает.
- *Pointer scatter* — радиальный толчок от курсора: частицы плавно разлетаются
  в стороны и потом сами замедляются. Основная реакция на мышь.
- *Pointer wind* — слабый общий снос по направлению движения курсора. Намеренно
  небольшой, чтобы поле расходилось, а не просто ехало за мышью.

**Разлёт.** Сила толчка спадает от курсора к границе радиуса и масштабируется
скоростью курсора, поэтому медленное движение расталкивает частицы мягче.
Скорость разлёта затухает по своему таймеру (`scatterTau`) и хранится отдельно
от сноса: снос постоянно подтягивается к цели, и если складывать их в одну
величину, радиальный импульс стирается ровно так же быстро, как появляется —
именно поэтому в первой версии частицы «слегка следовали за мышью» вместо того,
чтобы разлетаться.

Ближние по глубине частицы отвечают на курсор сильнее дальних, что даёт
параллакс. Всё сглаживание сделано через `1 - exp(-dt / tau)`, поэтому поведение
не зависит от частоты кадров.

Параметры пробрасываются пропсом `fieldOptions`:

```vue
<Error404
  :field-options="{
    scatterRadius: 300,    // радиус влияния курсора, css px
    scatterStrength: 650,  // сила разлёта, css px/s²
    scatterTau: 1.6,       // сколько частицы летят по инерции
    maxScatter: 320,       // потолок скорости разлёта, css px/s
    coupling: 0.09,        // насколько поле сносит по направлению мыши
    responseTau: 1.5,      // инерция сноса
    pointerTau: 0.35,      // сглаживание курсора: больше — мягче старт
  }"
/>
```

Ключевой параметр здесь — `maxScatter`. Без низкого потолка одного свайпа
хватает, чтобы вымести область почти полностью: замеры показали, что при
`maxScatter: 520` частицы уносит через половину экрана, и вместо расхождения
получается пылесос.

Помимо смещения по плоскости частицы медленно дрейфуют по глубине (`driftZ`).
Проход через фокальную плоскость меняет сразу размер, размытие и прозрачность,
поэтому он заметнее простого сдвига и как раз поддерживает ощущение объёма.
Прозрачность дополнительно очень медленно «дышит».

Амплитуды подобраны по измерениям кадров, а не на глаз: при исходных значениях
за 6 секунд простоя менялось слишком мало пикселей и поле читалось как
статичная картинка. На текущих настройках за те же 6 секунд заметно смещается
каждая частица, при этом разгон от мыши остаётся примерно в восемь раз сильнее
фонового дрейфа — то есть реакция на курсор хорошо различима на фоне постоянного
движения.

**Производительность и доступность.** Количество частиц считается от площади
вьюпорта (одна на ~12000 px², но не больше 155), DPR ограничен двойкой, `dt` в
кадре ограничен сверху. Цикл `rAF` ставится на паузу на скрытой вкладке, при
этом «нужна ли анимация» и «запущен ли цикл» — разные флаги, поэтому возврат на
вкладку не перезапускает анимацию, выключенную явно. При
`prefers-reduced-motion: reduce` рисуется один статичный кадр без цикла.

## Отличия от макета

- **Кнопки скруглены.** В макете `border-radius: 0`; здесь `18px` на десктопе и
  `14px` на мобиле. В остальном кнопки плоские, как везде на сайте: состояние
  передаётся только сменой заливки. На ховере светлая кнопка получает `#f1f5ee`
  — тот же тон, которым дизайн обозначает активный пункт меню, — а тёмная
  светлеет с `#121212` до `#2a2a2a`. Единственное движение — короткий сдвиг
  стрелки.
- **Шаг между кнопками** 10px вместо 8px — со скруглёнными углами так читается
  чище.
- **Опечатка в тексте.** В макете «Вернутся на главную», в коде — «Вернуться на
  главную».
- **Фон** собран градиентами вместо растра, см. раздел выше.
- **Плотность частиц** немного ниже макетной, прозрачность ограничена: при
  полном совпадении поле читалось как контрастное звёздное небо, а не как мягкая
  тёплая дымка.
